### Bug Fixes

* A `window.open` popup whose target URL is still empty is the document before its first commit, not a dead opener and not an `about:blank` success. `Page.frameStartedNavigating` on that popup names the destination while `TargetInfo.url` is empty. When that event names an http(s) URL and the original tab still answers, the click waits for the commit, including when the response takes longer than 3s, and then reports `opened new tab`. If the navigation does not commit and the original tab still answers, the command exits 1 with `Kind: popup-uncommitted`, says the original tab is still usable, and Next is `cdp list`. Do not repeat the click. If the original tab does not answer at the empty-url deadline, the click does not keep waiting out the navigation cap: it terminates execution on that tab and checks again. Closing the popup does not recover it. If it still does not answer, the command exits 1 with `Kind: opener-blocked`, says the original tab is no longer usable, and Next is `cdp open` of the original page. That stuck path, including terminate and the recheck, finishes within 9300ms, inside the live test's 20s limit. A later click on a tab that already does not answer probes it before the baseline, the form-control snapshot, and the locator. Those three evaluates otherwise wait 15000ms, 15000ms, and 17000ms (`Timeout` plus the 2000ms actionability wait) and the command exits `Kind: timeout`. The probe terminates once and checks again. If the tab still does not answer, the receipt is the same `opener-blocked` and the same Next. That pre-click path finishes within 2300ms. The opener live test requires that reopen URL to be the page that was open, and it no longer prints the branch it took ([#677](https://github.com/EndeavorYen/chrome-cdp-ex/issues/677), [#679](https://github.com/EndeavorYen/chrome-cdp-ex/issues/679)).
