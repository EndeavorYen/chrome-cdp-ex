# #419: `list_raw` args and pipe close, before and after (2026-10-01)

Evidence label: `local result` = measured on one Windows 11 machine (Node v24.21.0, headless Chrome 154) by the author of the change. Not measured on Linux or macOS, and not repeated on another machine.

Raw numbers: [`2026-10-01-issue-419-before.json`](2026-10-01-issue-419-before.json) (origin/main `2a6d67b`) and [`2026-10-01-issue-419-after.json`](2026-10-01-issue-419-after.json) (this branch). Cause analysis: [`2026-09-30-cli-preamble.md`](2026-09-30-cli-preamble.md).

## Setup

- Own headless Chrome: `chrome.exe --headless=new --remote-debugging-port=9345 --user-data-dir=<temp>`, two `about:blank` tabs, one per tree, so each tree has its own warm per-tab daemon. Chrome killed by PID afterwards.
- `CDP_PORT=9345`, and `LOCALAPPDATA` pointed at a scratch directory, so `pages.json` and the daemon list held only this browser's tabs.
- `scripts/benchmark-cli-overhead.mjs <tab> --runs 12` from each tree, interleaved: before r1, after r1, before r2, after r2. The machine was not idle: another Chrome job was running.

## Result (`local result`, median / p90 ms)

| Measure | before r1 | after r1 | before r2 | after r2 |
|---|---|---|---|---|
| `node -e 0` | 35 / 39 | 39 / 43 | 33 / 38 | 34 / 37 |
| `cdp help` | 88 / 102 | 80 / 90 | 93 / 98 | 77 / 81 |
| `cdp eval <tab> document.title` | 252 / 259 | 126 / 129 | 255 / 262 | 114 / 117 |
| `cdp batch <tab>` of 12 evals | 267 / 283 | 135 / 159 | 272 / 313 | 128 / 131 |

The issue's scratch-copy figure (245 ms to 117 ms per `cdp eval`) reproduced in this run: 252-255 ms before, 114-126 ms after.

Wall-clock probe on the same setup (`scripts/probe-cli-preamble.mjs <cdp.mjs> <tab> 6`, median of 6 warm runs, not committed as JSON):

| Segment (ms) | before | after |
|---|---|---|
| process exit (`exit_at`) | 261.7 | 121.1 |
| 3 target discoveries | 86.3 | 11.5 |
| wait after the `eval` reply (`tail_after_eval`) | 50.6 | 0.3 |

## What changed

1. Discovery sends `list_raw` with `args: []`, but only to a daemon that reports, through `meta`, the same `CDP_HOST:CDP_PORT` as the call. Without `CDP_PORT`, and with a daemon older than this change, discovery keeps the fresh browser connection. So the speed-up above needs `CDP_PORT` set.
2. After the reply frame, the CLI closes the daemon pipe with `destroy()` instead of `end()`.

The numbers were taken at commit `7653ba7`. The follow-up review commits only bound each daemon probe step to 1.5 s (no new probe after 3 s), stop after the first matching daemon, and stop `meta` / `list_raw` requests from resetting a daemon's idle timer; neither is on the timed path, and it was not re-measured.

Discovery still runs three times per call, the `git rev-parse` spawn and module load are unchanged (out of scope for #419).
