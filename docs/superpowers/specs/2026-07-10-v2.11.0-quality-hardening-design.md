# v2.11.0 Quality Hardening Design

**Status:** Approved by the user's request to complete every finding from the
2026-07-10 high-intensity review, merge it, and publish a release.

## Goal

Make the reviewed v2.10.0 surfaces trustworthy under real agent use: component
inspection must be private and bounded, shipped CLI flags must work end to end,
campaign failures must fail automation, route comparisons must execute the same
task, local product profiles must exercise distinct behavior, and low-token
paths must be available through both CLI guidance and MCP.

## Constraints

- Keep the runtime dependency-free and on Node.js 22+.
- Preserve existing command names and schemas where practical.
- Mutating MCP tools continue to require `confirm: true`.
- GitHub tags, Releases, Pages, and attached tarballs are the publish surface.
- Do not publish to the npm registry.
- Release from a clean `origin/main` only after local and GitHub gates pass.

## Runtime Contracts

### Component Inspection

`components` will recognize only actual ref forms (`@N`, `@cN`, and `@fN:M`),
so CSS pseudo-class selectors remain selectors. The ref path will pass
`resolveRefNode` arguments in the established order and use its returned
`objectId` directly.

Default component output will recursively redact sensitive keys with the same
policy used by action/checkpoint artifacts. Props and state will each have a
bounded serialized representation with explicit `truncated`, `originalChars`,
and `preview` metadata when they exceed the budget. `--unsafe-full` is the
explicit opt-in for unredacted, unbounded developer inspection. Tree summaries
will redact sensitive prop names before rendering their compact previews.

### CLI Flag Transport

The top-level `eval` argument normalizer will preserve `--raw` as a daemon
argument instead of concatenating it into JavaScript. Tests must execute the
same main-process normalization helper used by the CLI, not only
`parseEvalArgs` inside the daemon.

### Campaign Exit Semantics

The campaign summary remains available on stdout even when rounds fail, but the
CLI process exits non-zero when any planned round is incomplete/failed or when
a baseline comparison has status `fail`. `--allow-failures` is the explicit
diagnostic mode that retains exit zero.

### Real-App Profiles

Profiles will no longer share one trait list. Each profile owns a distinct
fixture contract:

| Profile | Distinct focus | Required exercised probe |
|---|---|---|
| `dashboard` | SPA route, slow refresh, large table | route and dashboard refresh |
| `docs-app` | iframe, shadow DOM, hidden templates | frame and shadow observation |
| `auth-flow` | auth wall, modal recovery, slow request | auth refresh and recovery |
| `data-table` | large table and hidden templates | bounded table extraction |
| `canvas-heavy` | canvas surface and visual state | canvas metadata and screenshot |

Campaign output will record the profile's expected and exercised probes. A
real-app round fails its gate when the profile-specific probe is missing.

### Matched MCP And CLI Routing

The route benchmark will use one shared task specification: open the same smoke
fixture, list controls, inspect overlay state, dismiss the modal, verify the
same click outcome, and request the same compact report window. MCP and CLI
runners will produce the same normalized metrics and gate expectations. Route
recommendations will compare `mcp` with the new matched `cli` type; killer-path
rounds are not route evidence.

### Bounded Agent Output

- Golden-path perceive recommendations use `--adaptive`.
- MCP `perceive` exposes `adaptive` and defaults it on unless the caller gives
  an explicit numeric `last`.
- MCP `report` defaults to compact JSON; callers may request full output.
- MCP/CLI `controls --compact` removes duplicate text/title/hint fields while
  preserving role, label, selector, state, and rectangle.
- Broadcast JSON defaults to bounded result previews. `--full-results` is the
  explicit verbose mode, and retry commands preserve original command args.

## Documentation And Dependency Gate

The contributor guidance will describe the current 14k-line command runtime
plus extracted libraries, correct the `skills/chrome-cdp-ex` path, and remove
shipped features from `DESIGN.md` future status. `check:docs` will read
`CLAUDE.md`, `CONTRIBUTING.md`, and `DESIGN.md` and reject the known stale
claims. Dev dependencies and the lockfile will be refreshed until
`npm audit --audit-level=high` passes.

## Verification

Every production change starts with a failing Vitest regression. Release proof
requires lint, full tests, docs contract, high-severity audit, package dry-run,
package content inspection, live smoke, a matched MCP/CLI campaign, and at
least 10 real browser rounds spanning MCP, CLI, killer, large-app, and all five
real-app profiles. The release notes must distinguish safe local fixtures from
external production applications.
