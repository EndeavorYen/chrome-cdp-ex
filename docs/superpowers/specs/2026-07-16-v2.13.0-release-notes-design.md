# v2.13.0 Release Notes Rewrite Design

## Goal

Rewrite the v2.13.0 changelog and published GitHub Release so they explain what changed for users between v2.12.0 and v2.13.0. Commit messages and the release PR remain traceability links, not the main narrative.

## Audience

The primary reader is an agent operator deciding whether to upgrade from v2.12.0. The secondary reader is a maintainer who needs issue and implementation traceability.

## Content Contract

Both surfaces must describe the same five behavior changes:

1. Responsive audits now find controls clipped inside nested containers and controls actually blocked by visible fixed, sticky, or dialog surfaces, while suppressing intentional scrolling.
2. Screenshot capture now distinguishes a legitimate dark page from a contradictory black frame, retries once through an alternate capture surface, and fails closed if the result remains unreliable.
3. Session reports no longer keep recommending recovery for an older failure after a newer action has been verified successful.
4. Action, perception, QA, and responsive checks now share page-health evidence, preventing a missing URL sample from turning a visibly populated page into a false blank result and exposing loading states as indeterminate.
5. Target commands resolve against live tabs first, detect daemon-to-tab identity mismatches, rebind once, and expose requested, bound, resolved, source, and status diagnostics.

## Information Hierarchy

### CHANGELOG.md

- Lead with a short release theme and an operator-facing summary.
- Use `Changed`, `Reliability`, and `Diagnostics` sections rather than implementation-oriented `Features` and `Fixes` buckets.
- Keep each item focused on the previous behavior, the new behavior, and why it matters.
- Preserve issue links for traceability.

### GitHub Release

- Start with a one-paragraph release summary.
- Add a compact Before/Now comparison table.
- Explain the five changes in realistic operator scenarios.
- State compatibility and upgrade impact: no command removals or required configuration migration; structured outputs only gain/clarify diagnostics.
- Include validation evidence, package asset, SHA-256 checksum, compare link, and PR/issue traceability at the end.

## Accuracy Boundaries

- Do not claim that every dark screenshot is an error; only a near-black frame that contradicts a computed light page is retried.
- Do not claim all overlaps are detected; findings are bounded and require material geometry plus visible hit-tested occlusion.
- Do not describe indeterminate page health as blank or pass.
- Do not imply npm registry publication. GitHub Releases remain the official distribution surface.
- Keep the existing v2.13.0 tag and tarball unchanged; this work changes explanatory text only.

## Acceptance Criteria

- A v2.12.0 user can identify the practical reason to upgrade without reading commits or issues.
- The changelog and GitHub Release agree on behavior, compatibility, asset name, and checksum.
- The release PR appears only in traceability, not as the release summary.
- Documentation checks pass and the published release is verified after editing.
